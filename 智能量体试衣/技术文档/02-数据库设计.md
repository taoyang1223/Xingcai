# 02 · 数据库设计文档

> 数据库：PostgreSQL 15（业务主库）、Redis 7（缓存）、OSS（对象存储）
> 范围：MVP（P1）全量表 + 二期表的边界预留
> 关联：《01-技术架构设计》第 4 章模块划分、《06-安全与合规设计》

---

## 1. 设计约定

**命名**：表名小写复数下划线（`body_profiles`）；模块前缀用于区分归属（`cat_`=catalog，`rec_`=recommend，`adm_`=admin）；主键统一 `id BIGSERIAL`，对外暴露用 `uid`（雪花 ID 或 UUID），**绝不把自增 ID 暴露给客户端**（防遍历）。

**通用字段**：所有业务表带 `created_at`、`updated_at`；需软删的带 `deleted_at`。审计日志表只追加，不带 `updated_at`。

**跨模块禁止外键**：模块内可用外键，跨模块只存 ID 不建 FK，为将来拆库留路（对应 ADR-01 的模块化纪律）。

**金额**：`NUMERIC(12,2)`，单位元。**尺寸**：`NUMERIC(5,1)`，单位厘米，保留一位小数。

**加密**：标记 🔐 的字段做**应用层字段级加密**（AES-256-GCM，密钥走 KMS，加密后存 `BYTEA`）。不用数据库透明加密，因为威胁模型包含"后台账号被盗用后拖库"。

## 3. 核心表结构

### 3.1 identity 用户域

```sql
CREATE TABLE users (
    id           BIGSERIAL PRIMARY KEY,
    uid          VARCHAR(32)  NOT NULL UNIQUE,           -- 对外 ID
    phone_hash   VARCHAR(64)  NOT NULL UNIQUE,           -- 手机号 HMAC，用于查找
    phone_enc    BYTEA        NOT NULL,                  -- 🔐 手机号密文
    nickname     VARCHAR(64),
    avatar_url   VARCHAR(512),
    gender       SMALLINT     NOT NULL DEFAULT 0,        -- 0未知 1男 2女（影响体型基与尺码表）
    birth_year   SMALLINT,                               -- 只存年份，不存完整生日（最小化）
    status       SMALLINT     NOT NULL DEFAULT 1,        -- 1正常 2封禁 3注销中 4已注销
    registered_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    deleted_at   TIMESTAMPTZ,
    created_at   TIMESTAMPTZ  NOT NULL DEFAULT now(),
    updated_at   TIMESTAMPTZ  NOT NULL DEFAULT now()
);

CREATE TABLE user_auths (                                 -- 多登录方式
    id           BIGSERIAL PRIMARY KEY,
    user_id      BIGINT      NOT NULL REFERENCES users(id),
    provider     VARCHAR(16) NOT NULL,                   -- phone/wechat/apple
    open_id      VARCHAR(128) NOT NULL,
    credential   BYTEA,                                  -- 🔐
    UNIQUE (provider, open_id)
);

-- 同意记录：合规核心，PIPL 要求可证明"何时以何种方式取得了单独同意"
CREATE TABLE consents (
    id            BIGSERIAL PRIMARY KEY,
    user_id       BIGINT      NOT NULL,
    scene         VARCHAR(32) NOT NULL,      -- body_photo / body_data_train / share_third_party
    policy_version VARCHAR(16) NOT NULL,     -- 对应隐私政策版本号
    granted       BOOLEAN     NOT NULL,
    granted_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    revoked_at    TIMESTAMPTZ,
    client_ip     INET,
    device_info   JSONB,
    UNIQUE (user_id, scene, policy_version)
);
CREATE INDEX idx_consents_user ON consents(user_id, scene);
```

> **`consents` 表不可省略**。将来监管或纠纷时，"用户同意过"必须拿得出证据链：哪个版本的政策、什么时间、什么设备。

### 3.2 body 身体域（全表敏感，独立权限域）

```sql
CREATE TABLE body_profiles (
    id           BIGSERIAL PRIMARY KEY,
    uid          VARCHAR(32) NOT NULL UNIQUE,
    user_id      BIGINT      NOT NULL,
    name         VARCHAR(32) NOT NULL DEFAULT '我',       -- 多档案：本人/伴侣/父母(A-2)
    relation     VARCHAR(16) NOT NULL DEFAULT 'self',
    gender       SMALLINT    NOT NULL,
    age_range    VARCHAR(16),
    height_cm    NUMERIC(4,1) NOT NULL,
    weight_kg    NUMERIC(4,1) NOT NULL,
    body_shape   VARCHAR(16),                             -- hourglass/pear/apple/rectangle/inverted_triangle
    source       VARCHAR(16) NOT NULL,                    -- manual / photo / video / lidar
    is_default   BOOLEAN     NOT NULL DEFAULT false,
    version      INT         NOT NULL DEFAULT 1,          -- 每次重建或修正 +1，用于推荐缓存失效
    deleted_at   TIMESTAMPTZ,
    created_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_body_profiles_user ON body_profiles(user_id) WHERE deleted_at IS NULL;

-- 围度：一行一档案一版本，所有围度打包进加密列
CREATE TABLE body_measurements (
    id             BIGSERIAL PRIMARY KEY,
    profile_id     BIGINT      NOT NULL,
    profile_version INT        NOT NULL,
    measures_enc   BYTEA       NOT NULL,   -- 🔐 JSON: {"chest":96.2,"waist":81.0,...} 见附录字典
    confidence     JSONB       NOT NULL,   -- {"chest":0.92,"waist":0.71,...} 非敏感，明文便于统计
    corrected_by_user JSONB,               -- {"waist":{"from":81.0,"to":84.0}} 🔐? 仅存差值，用于算法回流
    provider_code  VARCHAR(32),            -- 由哪家 SDK 产出，对应 J-9 的 A/B
    measured_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (profile_id, profile_version)
);

CREATE TABLE body_model_assets (
    id           BIGSERIAL PRIMARY KEY,
    profile_id   BIGINT      NOT NULL,
    profile_version INT      NOT NULL,
    mesh_key     VARCHAR(256) NOT NULL,    -- OSS key，访问一律用短时效签名 URL
    format       VARCHAR(16)  NOT NULL,    -- gltf / glb
    lod          SMALLINT     NOT NULL DEFAULT 0,
    size_bytes   INT,
    created_at   TIMESTAMPTZ  NOT NULL DEFAULT now()
);

CREATE TABLE body_measure_jobs (
    id            BIGSERIAL PRIMARY KEY,
    job_uid       VARCHAR(32) NOT NULL UNIQUE,
    user_id       BIGINT      NOT NULL,
    profile_id    BIGINT,
    consent_id    BIGINT      NOT NULL,          -- 无同意记录不允许建模，代码层强校验
    status        VARCHAR(16) NOT NULL,          -- PENDING/RUNNING/SUCCEEDED/FAILED/TIMEOUT
    provider_code VARCHAR(32),
    photo_keys    JSONB,                         -- 原图 OSS key，任务完成后置空
    photo_purged_at TIMESTAMPTZ,                 -- 原图删除时间，合规审计要查
    error_code    VARCHAR(32),
    cost_ms       INT,
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    finished_at   TIMESTAMPTZ
);
CREATE INDEX idx_jobs_status ON body_measure_jobs(status, created_at);
```

> `photo_purged_at` 为空且 `finished_at` 超过 1 小时的记录，应触发**告警**——说明删图流程出问题了，这是合规事故的前兆。

### 3.3 catalog 商品域

```sql
CREATE TABLE cat_categories (
    id          BIGSERIAL PRIMARY KEY,
    code        VARCHAR(32) NOT NULL UNIQUE,   -- tshirt/shirt/dress/pants/skirt/coat...
    name        VARCHAR(32) NOT NULL,
    parent_code VARCHAR(32),
    body_part   VARCHAR(16) NOT NULL,          -- upper/lower/whole
    sort        INT DEFAULT 0,
    enabled     BOOLEAN NOT NULL DEFAULT true
);

-- 品类字段模板（PRD C-2b）：决定该品类要比对哪些部位，运营可配
CREATE TABLE cat_field_templates (
    id             BIGSERIAL PRIMARY KEY,
    category_code  VARCHAR(32) NOT NULL,
    version        INT         NOT NULL,
    required_fields JSONB      NOT NULL,  -- ["chest","shoulder","garment_length","sleeve_length"]
    optional_fields JSONB      NOT NULL,
    alias_dict     JSONB       NOT NULL,  -- {"胸围":"chest","衣宽":"chest_flat","净胸围":"chest"}
    measure_mode   JSONB       NOT NULL,  -- {"chest":"flat_x2"} 平铺量*2 还是围量，口径极易出错
    status         VARCHAR(16) NOT NULL DEFAULT 'draft',  -- draft/published/archived
    published_at   TIMESTAMPTZ,
    UNIQUE (category_code, version)
);

CREATE TABLE cat_brands (
    id          BIGSERIAL PRIMARY KEY,
    code        VARCHAR(64) NOT NULL UNIQUE,
    name        VARCHAR(128) NOT NULL,
    platform    VARCHAR(16),
    shop_id     VARCHAR(64),
    trust_score NUMERIC(3,2) DEFAULT 0.50,   -- 尺码表可信度，由反馈数据迭代
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE cat_products (
    id             BIGSERIAL PRIMARY KEY,
    uid            VARCHAR(32) NOT NULL UNIQUE,
    platform       VARCHAR(16) NOT NULL,           -- taobao/tmall/jd/...
    platform_item_id VARCHAR(64) NOT NULL,
    brand_id       BIGINT,
    category_code  VARCHAR(32),
    title          VARCHAR(512),
    cover_url      VARCHAR(512),
    fabric_desc    VARCHAR(512),                   -- 成分描述原文
    elasticity     VARCHAR(16),                    -- none/low/medium/high，由成分推断
    fit_type       VARCHAR(16),                    -- slim/regular/loose/oversize
    source_type    VARCHAR(16) NOT NULL,           -- api/share_parse/manual
    parse_status   VARCHAR(16) NOT NULL,           -- ok/partial/failed/reviewing
    raw_payload    JSONB,                          -- 原始抓取数据，便于回溯与重跑
    last_parsed_at TIMESTAMPTZ,
    UNIQUE (platform, platform_item_id)
);
CREATE INDEX idx_products_status ON cat_products(parse_status) WHERE parse_status IN ('failed','reviewing');

CREATE TABLE cat_size_charts (
    id            BIGSERIAL PRIMARY KEY,
    product_id    BIGINT      NOT NULL,
    version       INT         NOT NULL DEFAULT 1,
    chart_hash    VARCHAR(64) NOT NULL,       -- 内容哈希，用于判断商家是否改过尺码表
    size_system   VARCHAR(16),                -- CN/EU/US/JP/FREE
    unit          VARCHAR(8) NOT NULL DEFAULT 'cm',
    measure_mode  VARCHAR(16),                -- flat(平铺) / circumference(围量)
    source        VARCHAR(16) NOT NULL,       -- structured/ocr/manual
    ocr_confidence NUMERIC(3,2),
    reviewed_by   BIGINT,                     -- 人工审核人，NULL 表示未审
    reviewed_at   TIMESTAMPTZ,
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (product_id, version)
);

CREATE TABLE cat_size_entries (
    id           BIGSERIAL PRIMARY KEY,
    chart_id     BIGINT      NOT NULL,
    size_label   VARCHAR(16) NOT NULL,        -- S/M/L/165/90A
    size_order   SMALLINT    NOT NULL,        -- 排序，用于"大一码/小一码"
    values       JSONB       NOT NULL,        -- {"chest":108,"shoulder":44,"sleeve_length":58.5}
    UNIQUE (chart_id, size_label)
);

-- 品牌/店铺尺码偏差档案（PRD C-4），由反馈数据回流
CREATE TABLE cat_brand_bias (
    id            BIGSERIAL PRIMARY KEY,
    brand_id      BIGINT      NOT NULL,
    category_code VARCHAR(32) NOT NULL,
    part          VARCHAR(24) NOT NULL,       -- chest/waist/...
    bias_cm       NUMERIC(4,1) NOT NULL,      -- 实测 - 标称，正数=偏大
    sample_count  INT         NOT NULL,
    confidence    NUMERIC(3,2) NOT NULL,
    updated_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (brand_id, category_code, part)
);
```

> `chart_hash` 这个字段很重要：商家经常悄悄改尺码表。没有它，你的推荐会基于过期数据，而且事后无法解释"为什么当时推荐了 L"。

### 3.4 recommend 推荐域

```sql
CREATE TABLE rec_records (
    id              BIGSERIAL PRIMARY KEY,
    uid             VARCHAR(32) NOT NULL UNIQUE,
    user_id         BIGINT      NOT NULL,
    profile_id      BIGINT      NOT NULL,
    profile_version INT         NOT NULL,      -- 快照：身体数据版本
    product_id      BIGINT      NOT NULL,
    chart_id        BIGINT      NOT NULL,      -- 快照：用了哪版尺码表
    rule_version    VARCHAR(32) NOT NULL,      -- 快照：用了哪版松量规则
    preference      VARCHAR(16) NOT NULL,      -- tight/regular/loose
    recommended_size VARCHAR(16),
    confidence      NUMERIC(3,2),
    alternatives    JSONB,
    overall_risk    VARCHAR(16),               -- low/medium/high/no_fit
    reason_text     VARCHAR(512),
    engine_version  VARCHAR(32) NOT NULL,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_rec_user_time ON rec_records(user_id, created_at DESC);
CREATE INDEX idx_rec_product ON rec_records(product_id, created_at DESC);

CREATE TABLE rec_fit_details (
    id            BIGSERIAL PRIMARY KEY,
    record_id     BIGINT      NOT NULL,
    size_label    VARCHAR(16) NOT NULL,        -- 每个候选码都存，支持"M/L 对比"
    part          VARCHAR(24) NOT NULL,
    user_cm       NUMERIC(5,1),
    garment_cm    NUMERIC(5,1),
    ease_cm       NUMERIC(5,1),
    verdict       VARCHAR(16) NOT NULL,        -- tight/fit/comfortable/loose/too_loose/short/long
    tip           VARCHAR(128)
);
CREATE INDEX idx_fit_record ON rec_fit_details(record_id);
```

> 四个 `*_version` 快照字段是**可解释性的基础**。用户三个月后问"你当时为什么推荐 L"，靠它们才能完整复现当时的计算。没有快照，推荐系统就是黑盒，出了纠纷无法自证。

### 3.6 config 配置域（松量规则是推荐引擎的心脏）

```sql
CREATE TABLE cfg_ease_rules (
    id            BIGSERIAL PRIMARY KEY,
    rule_set_version VARCHAR(32) NOT NULL,      -- 与 rec_records.rule_version 对应
    category_code VARCHAR(32) NOT NULL,
    fit_type      VARCHAR(16) NOT NULL,         -- slim/regular/loose/oversize
    elasticity    VARCHAR(16) NOT NULL,         -- none/low/medium/high
    part          VARCHAR(24) NOT NULL,
    ease_min_cm   NUMERIC(4,1) NOT NULL,        -- 可为负（高弹面料允许负松量）
    ease_ideal_cm NUMERIC(4,1) NOT NULL,
    ease_max_cm   NUMERIC(4,1) NOT NULL,
    weight        NUMERIC(3,2) NOT NULL DEFAULT 1.00,  -- 该部位在总分中的权重
    UNIQUE (rule_set_version, category_code, fit_type, elasticity, part)
);

CREATE TABLE cfg_rule_sets (
    version      VARCHAR(32) PRIMARY KEY,
    status       VARCHAR(16) NOT NULL,          -- draft/gray/published/archived
    gray_percent SMALLINT DEFAULT 0,
    note         VARCHAR(256),
    created_by   BIGINT,
    published_at TIMESTAMPTZ
);

CREATE TABLE cfg_flags (
    key          VARCHAR(64) PRIMARY KEY,
    value        JSONB NOT NULL,
    description  VARCHAR(256),
    updated_by   BIGINT,
    updated_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

> 松量规则**必须版本化 + 可灰度**。调错一条规则，影响的是全站推荐准确率；没有版本就无法回滚，没有灰度就只能全量赌。

## 4. Redis 键设计

| Key 模式 | 类型 | TTL | 用途 |
| --- | --- | --- | --- |
| `sess:{token_id}` | Hash | 7d | 会话 |
| `prod:parse:{platform}:{item_id}` | String(JSON) | 7d | 商品解析结果缓存 |
| `rec:{profile_uid}:{pv}:{chart_hash}:{pref}` | String(JSON) | 1d | 推荐结果缓存 |
| `rl:{scope}:{id}` | String | 60s | 限流计数 |
| `job:{job_uid}` | Hash | 2h | 建模任务状态（高频轮询，不打库） |
| `lock:{biz}:{id}` | String | 30s | 分布式锁（幂等） |

## 5. 数据生命周期与保留策略

| 数据 | 保留期 | 处理方式 |
| --- | --- | --- |
| 原始人体照片 | **≤ 1 小时** | 任务完成即删 + 桶生命周期兜底；单独授权做训练集的另存隔离桶并脱敏 |
| 围度与 3D 模型 | 账号存续期 | 用户可随时删除；注销后 T+15 日内彻底清除（含备份） |
| 推荐记录 | 2 年 | 超期归档，保留统计维度、去除用户关联 |
| 反馈数据 | 长期 | 去标识化后可长期用于算法 |
| 审计日志 | ≥ 3 年 | 只追加，独立权限，运维不可删 |
| 数据库备份 | 全量 7 日 + 增量 | 注销清除任务需覆盖备份，见文档 06 |

## 6. 性能与扩展预案

- **索引原则**：所有列表查询必有覆盖索引；`rec_records`、`fb_fit_feedbacks` 按 `created_at` 做时间范围查询，后续按月分区。
- **分区**：`adm_audit_logs` 上线即按月分区；`rec_records` 达到 5000 万行时再分区（预计 P3 之后）。
- **读写分离**：后台看板查询一律走只读从库，**禁止后台大查询打主库**——这是最常见的线上事故来源。
- **分库分表**：MVP 不做。触发条件是单表 >2 亿行或写入 >5000 TPS，届时按 `user_id` 分片 `body_*` 与 `rec_*`。
- **JSONB 使用纪律**：`values`、`alias_dict` 这类结构多变的用 JSONB；但**参与计算和筛选的关键字段必须提列**，不要把 `chest` 埋在 JSONB 里再去 where。
